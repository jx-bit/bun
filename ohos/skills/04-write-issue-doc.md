## Skill 4：写 Issue 分析文档

### 目的

把一个问题（或一组相关问题）的前因后果写成结构化文档，存到 `ohos/issues/` 下（按 `pr<N>-p<优先级>-<关键词>.md` 命名与 PR 关联，见 issues/README.md）。

### 文件命名

```
ohos/issues/pr<N>-p<优先级>-<问题关键词>.md
```

| 优先级 | 含义 |
|---|---|
| P0 | 阻断构建（编译失败） |
| P1 | 导致测试回归（用例失败） |
| P2 | 功能不完整（不影响编译和已有用例） |
| P3 | 不阻断（lint、格式、排序） |

### 文档结构模板

```markdown
# P<N>: <问题标题> — 详细讲解

> 用最简单的方式讲清楚：这是什么、为什么发生、有什么后果、怎么修。

---

## 1. 背景知识
（通俗比喻 + 技术含义）

## 1.5 用户影响速览（必填）
| 用户在做什么 | 感知症状 | 频率 | 严重度 | 修复后 |
|---|---|---|---|---|
（每个缺陷一行；感知症状必须写用户看到的表现，禁止只写内部机制；
根因给工程师，用户影响给排优先级和验收的人，两者缺一不可）

## 2. 问题是什么
### 2.1 我们做了什么
### 2.2 为什么要这样做
### 2.3 这样做的副作用

## 3. social4hyq 怎么做的
（他们的方案 + 为什么可行 + 和我们的差异）

## 4. ljy9812 怎么做的
（和我们的异同）

## 5. 修复方案
（多个方案对比 + 推荐方案 + 为什么推荐）

## 6. 涉及的文件

## 7. 验证方法

## 8. 术语速查
```

### 示例文件

- `pr1-p0-symbols-dyn-trimming.md` — symbols.dyn 裁剪 + 自编译 __n1 libc++（519 行）
- `pr5-p1-highway-sve-disabling.md` — Highway SVE 禁用 → 32 用例回归（PR#5 修复）
- `pr6-p2-linker-lds-shim-symbols-incomplete.md` — shim 符号 8→15 补全（PR#6）
- `pr7-p2-run-command-gates-incomplete.md` — run_command.rs OHOS gate 补全（PR#7）
- `pr8-p3-source-lints.md` — Source lints 一致性检查（含三方对比）
